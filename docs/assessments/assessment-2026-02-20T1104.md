### Key Technical Decisions Made

1. **Cargo workspace refactor** — Extracted `surreal-memory` as a standalone library crate. This enables independent crates.io publication and clean separation of concerns between the binary server and the embeddable library.

2. **RocksDB+tempdir for integration tests** — `kv-mem` (SurrealDB in-memory engine) requires `surrealmx ≥ 0.17` which doesn't exist in crates.io for SurrealDB 3.0.0. Switched to embedded RocksDB with unique nanosecond-timestamped temp directories per test. This is zero-dependency (no external server) and fully parallel-safe.

3. **BM25 removed from embedded migration** — `DEFINE ANALYZER IF NOT EXISTS` and SEARCH ANALYZER BM25 indexes cause parse errors in SurrealDB 3.0.0 embedded mode. The BM25 indexes were removed from migration v6 and are applied separately in server mode. HNSW vector search covers semantic retrieval in all modes.

4. **`TYPE any` for enum-backed schema fields** — `MemoryType`, `MemoryScope`, `TaskStreamStatus`, `MapType` enums serialized via `SurrealValue` derive produce tagged objects (e.g. `{ Semantic: {} }`), but schema validation (`TYPE string`) rejects them. Widened to `TYPE any` to accept both the tagged-object form (from Rust) and plain string defaults.

5. **Migration v6 parse error fix** — `DEFINE ANALYZER IF NOT EXISTS` is not supported syntax in SurrealDB 3.0.0 embedded. Removed `IF NOT EXISTS` and later removed BM25 indexes entirely after confirming they require server-mode execution.

6. **A2A SSE** — Implemented as a streaming endpoint (not just a stub) that tails task stream events. This positions the server for agent-to-agent coordination without requiring a separate messaging layer.

7. **TTL decay worker** — Background `tokio::spawn` task that wakes on a configurable interval and deletes expired memories. Designed to be non-blocking and fault-tolerant (logs errors, continues on failure).

### Lessons Learned

1. **`kv-mem` trap in SurrealDB 3.0** — The in-memory engine is advertised in documentation but `surrealmx 0.17` doesn't exist yet in crates.io. Always verify dependency availability before designing test infrastructure around it.

2. **`DEFINE ANALYZER IF NOT EXISTS` not universally supported** — This syntax works in SurrealDB server but fails in the embedded engine. Always test DDL in both modes when targeting embedded deployment.

3. **SurrealValue enum serialization** — The `#[derive(SurrealValue)]` macro on enums produces tagged-object representation (`{ Variant: {} }`), not plain strings. If your schema expects `TYPE string`, widen to `TYPE any` or implement custom `serde` to emit bare strings.

4. **git filter-branch for accidental secrets** — GitHub Push Protection correctly blocked the first push due to an OpenAI key in `.roo/mcp.json` (a developer tooling config, not production code). `git filter-branch --index-filter` reliably scrubs specific files from all commits without rewriting any other content.

## Key Insights (Top 5)

1. **The enum serialization mismatch is a recurring SurrealDB + Rust footgun.** Any Rust enum stored in a SCHEMAFULL SurrealDB table with `TYPE string` will fail at runtime if the field was written by deserializing a plain-string DB default and reading it back as a tagged Rust enum via `SurrealValue`. The fix is `TYPE any` in the schema or a custom `serde(try_from = "String")` impl.

2. **`kv-mem` availability should always be verified before designing tests.** The SurrealDB in-memory engine sounds ideal for unit tests but its dependency (`surrealmx`) may not be published on crates.io for the version you're using. `RocksDB+tempdir` is a reliable fallback that requires no extra feature flags.

3. **Cargo workspaces are the right architecture for MCP servers with embeddable libraries.** Splitting the memory logic into `crates/surreal-memory` as a publishable library (with its own `Cargo.toml`, README, tests, and integration surface) creates immediate value — developers can embed the memory system in any Rust project without running a full server.

4. **GitHub Push Protection is a friend, not an enemy.** It correctly identified an OpenAI key in a developer tooling config that was accidentally staged. `git filter-branch` is the right tool for scrubbing specific files from all commits when the remote branch doesn't exist yet.

5. **4 unique features with no direct competitor analogs are a strong moat.** TaskStreams (model-aware token budgets + auto-summarization), Model Profiles (per-model context budget registry), Mindmaps (5 semantic map types + export), and A2A SSE streaming together form a capability cluster that none of the benchmarked competitors (Graphiti, mem0, Cognee, Basic Memory) have. This is the primary long-term differentiator.
