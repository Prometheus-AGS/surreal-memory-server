# MCP, REST, And Storage Contract Matrix

This document is the human-readable contract for the entity, memory, and
mindmap surfaces exposed to AI agents. The machine-readable JSON contracts live
in `docs/specs/mcp-tools.json` and `docs/specs/rest-api.json`; tests assert that
those files match the contract metadata generated by the server code.

## Entity Operations

| Operation | REST | MCP Tool | Request Fields | Success Response | Validation And Errors | Storage |
| --- | --- | --- | --- | --- | --- | --- |
| Create entity | `POST /api/v1/entities` | `create_entity` | `name`, `entity_type`, `observations` | `201` / JSON `Entity`; MCP text containing JSON `Entity` | `name` and `entity_type` must be non-empty; `observations` must contain at least one non-empty item; duplicate names are bad requests | `MemoryStorage::create_entity` |
| Create entities | `POST /api/v1/entities/batch` | `create_entities` | REST array of create entity bodies; MCP `{ entities: [...] }` | JSON array of `Entity` | Batch must be non-empty; every item follows create-entity validation before any storage call | `MemoryStorage::create_entities` |
| Add observations | `POST /api/v1/entities/{name}/observations` | `add_observations` | `observations` plus path/tool entity name | JSON `Entity` | Entity name must be non-empty; observations must contain at least one non-empty item; missing entity is not found | `MemoryStorage::add_observations` |
| Create relation | `POST /api/v1/entities/relations` | `create_relation` | `from`, `to`, `relation_type` | `201` / JSON `Relation`; MCP text containing JSON `Relation` | Source, target, and relation type must be non-empty; source and target must differ; missing endpoints are bad requests | `MemoryStorage::create_relation` |
| Create relations | `POST /api/v1/entities/relations/batch` | `create_relations` | REST array of relation bodies; MCP `{ relations: [...] }` | JSON array of `Relation` | Batch must be non-empty; every item follows create-relation validation before any storage call | `MemoryStorage::create_relations` |
| Search entities | `GET /api/v1/entities/search?q=...` | `search_entities` | `q` / `query` | JSON array of entities | Query must be non-empty for MCP; REST treats missing `q` as empty search for backwards compatibility | `MemoryStorage::search_entities` |
| Delete entity | `DELETE /api/v1/entities/{name}` | `delete_entity` | path/tool `name` | `204`; MCP text summary | Name must be non-empty; missing entity is not found | `MemoryStorage::delete_entity` |

MCP also exposes graph-only tools that REST does not currently mirror:
`get_entity`, `update_entity`, `get_relations`, `get_entity_history`,
`get_graph_at_time`, `delete_relation`, and `semantic_search`.

## Memory Operations

| Operation | REST | MCP Tool | Request Fields | Success Response | Validation And Errors | Storage |
| --- | --- | --- | --- | --- | --- | --- |
| Add memory | `POST /api/v1/memory` | `add_memory` | `content`, optional `user_id`, `agent_id`, `session_id`, `categories` | `201` / JSON `Memory`; MCP text containing JSON `Memory` | `content` must be non-empty; embedding and deduplication errors propagate through the shared error model | `MemoryStorage::add_memory` |
| Get memory | `GET /api/v1/memory/{id}` | `get_memory` | path/tool `id` | JSON `Memory` | Missing memory returns REST `404`; MCP returns JSON `null` for backwards compatibility unless changed in a future contract version | `MemoryStorage::get_memory` |
| Update memory | `PUT /api/v1/memory/{id}` | `update_memory` | `content` plus path/tool `id` | JSON `Memory` | `content` must be non-empty; missing memory is not found | `MemoryStorage::update_memory` |
| Delete memory | `DELETE /api/v1/memory/{id}` | `delete_memory` | path/tool `id` | `204`; MCP text summary | Missing memory is not found | `MemoryStorage::delete_memory` |
| List memories | `GET /api/v1/memory` | `get_all_memories` | optional `user_id`, `agent_id`, `session_id` | JSON array of `Memory` | Scope filters are optional | `MemoryStorage::get_all_memories` |
| Delete memories | `DELETE /api/v1/memory` | `delete_all_memories` | optional `user_id`, `agent_id`, `session_id` | JSON `{ deleted }` | Scope filters are optional | `MemoryStorage::delete_all_memories` |

`Memory::new` currently stores provided IDs but leaves `scope` at its default
`global` value. The REST and MCP contracts preserve that behavior until a
separate migration/behavior change explicitly derives `scope` from the supplied
IDs.

## Mindmap Operations

| Operation | REST | MCP Tool | Request Fields | Success Response | Validation And Errors | Storage |
| --- | --- | --- | --- | --- | --- | --- |
| Create mindmap | `POST /api/v1/mindmaps` | `create_mindmap` | `name`, optional `map_type`, `root_label`, optional `description`, `agent_id`, `user_id`, `task_stream_id`, `tags` | `201` / JSON `MindMap`; MCP text containing JSON `MindMap` | `name` and `root_label` must be non-empty; `map_type` must be one of `radial`, `concept`, `argument`, `tree`, `temporal`; invalid `task_stream_id` is a bad request | `MemoryStorage::create_mindmap` |
| List mindmaps | `GET /api/v1/mindmaps` | `list_mindmaps` | optional `user_id`, `agent_id` | JSON array of `MindMap` | Scope filters are optional | `MemoryStorage::list_mindmaps` |
| Get mindmap | `GET /api/v1/mindmaps/{name}` | `get_mindmap` | path/tool `name`, optional scope | JSON `MindMap` | REST returns `404` for missing maps; MCP returns JSON `null` for backwards compatibility unless changed in a future contract version | `MemoryStorage::get_mindmap` |
| Delete mindmap | `DELETE /api/v1/mindmaps/{name}` | `delete_mindmap` | path/tool `name`, optional scope | `204`; MCP text summary | Missing map is not found | `MemoryStorage::delete_mindmap` |
| Add node | `POST /api/v1/mindmaps/{name}/nodes` | `add_mindmap_node` | `node_id`, `label`, optional `parent_id`, `node_type`, `color`, `metadata` | JSON `MindMap` | `node_id` and `label` must be non-empty; nested JSON metadata is supported | `MemoryStorage::add_mindmap_node` |
| Delete node | `DELETE /api/v1/mindmaps/{name}/nodes/{node_id}` | `delete_mindmap_node` | `node_id` plus map name/scope | JSON `MindMap` | Missing node is not found | `MemoryStorage::delete_mindmap_node` |
| Add edge | `POST /api/v1/mindmaps/{name}/edges` | `add_mindmap_edge` | `from_id`, `to_id`, optional `label`, `directed` | JSON `MindMap` | `from_id` and `to_id` must be non-empty and must differ | `MemoryStorage::add_mindmap_edge` |
| Export | `GET /api/v1/mindmaps/{name}/export` | `export_mindmap` | `format` as `json`, `mermaid`, `markdown`, or `md` | Plain text export | Unknown REST format falls back to JSON for backwards compatibility; MCP format should match the documented values | `MindMap::export` |

## Verification

Run focused checks after changing these contracts:

```bash
cargo run --features embedded --bin export_contract_specs
cargo fmt --all --check
cargo test --features embedded --test contract_alignment_test
cargo test --features embedded api
cargo test --features embedded mcp
```

Server-mode smoke tests require a running server. Start it with a fixed port and
point the tests at it:

```bash
API_PORT=23001 MCP_STDIO=false cargo run --features embedded
TEST_API_BASE=http://127.0.0.1:23001 cargo test --features embedded --test mindmap_server_mode --test taskstream_server_mode -- --ignored
```
