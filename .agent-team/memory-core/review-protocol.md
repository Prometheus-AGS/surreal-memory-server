# Independent review

Use the installed adversarial-review skill when available. Build a packet with user intent, scope, final artifacts/diff, native frontmatter, skill provenance, actual graph/native check receipts and known limits. Include file hashes when repeated prompt bodies are represented once. State truncation explicitly. Exclude producer reasoning and preferred verdict.

Prefer a verified different-family judge through the configured model gateway. Do not copy credentials into artifacts or start new services. If unreachable, use a fresh native subagent with only the packet and artifact-review mandate; record `harness-native` and same-family limitation. If none completes, record pending review, not a pass. A reviewer can read actual artifacts, but owns only its findings file.

Findings contain severity (CRITICAL/WARNING/SUGGESTION), file/line, claim, evidence, suggested fix and a falsifier/reproduction where relevant. No finding quota and no praise padding. CRITICAL blocks certification until revised/reviewed. Keep independent findings unchanged; record remediation separately. Review only necessary changes after a finding, not repeated passing application tests.

Run the sycophancy-correction detector on descriptors and findings when available. A score alone is not proof of quality: examine the patterns, correct unsupported praise/agreement and distinguish intent from demonstrated behavior. Record unavailable tools and manual fallback honestly.

For this tooling setup: verify source selection/hashes, extraction failures, graph diagnostics, actual stdio MCP stats and a known call, all five native exports, local skill references/provenance, shared-file assignments and pre-existing file preservation. Do not compile/start the application or write to its databases as a configuration smoke test.
